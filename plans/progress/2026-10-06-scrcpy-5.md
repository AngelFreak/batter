## Local end-to-end on runcho (second pass, same day)

**Rig.** The built image `batter:scrcpy5-test` ran on the host network, with both
servers bound to 127.0.0.1 (the image's start script was overridden, since it binds
Next to 0.0.0.0). It used a throwaway `postgres:16-alpine` on 127.0.0.1:55432, and the
real **scrcpy-server 5.0** from the image, pushed to a dedicated emulator
(`batter-scrcpy5`, Android 16 / API 36, 1080×2400, port 5600). The image's adb
server ran on :5038 with emulator auto-scan off, connected only to that emulator,
so another session's emulator and adb on :5037 were left alone. Docker and KVM
work through `sg`: the account is in both groups, but this session predates that.

Also on runcho:
- **`go test ./...` with nothing skipped**: 145 tests, including the DB-backed
  `fakeadb` tests, with `BATTER_TEST_DATABASE_URL` and `adb` on PATH.
- **`docker build`** (BuildKit; a user-level `docker-buildx` v0.37.2 plugin was
  installed with its checksum verified, because the legacy builder can't do the
  Dockerfile's heredoc) prints `/scrcpy-server: OK`. A build with a wrong
  `SCRCPY_SERVER_SHA256` **fails** at that step.
- **Docker ITs** `proxyit` and `vpnit` pass. `proxyit` needed `caddy:2.11-alpine`
  pre-pulled. `vpnit` fails as-is on Ubuntu 26.04, whose AppArmor `wg` profile
  confines `wg` inside containers too and allows keys only under `/etc/wireguard`.
  The test helper `test/vpnit/wgserver.sh` writes `/server.key`. With a temporary,
  reverted edit that moved it under `/etc/wireguard`, the test passes, so Batter's
  own `wg setconf … /dev/stdin` is fine. The helper is a separate fix.

Tweak from this pass: the server sends a session packet at every capture start,
including encoder resets for joining viewers, so "video size changed" fired with an
unchanged size. Now it's only set and logged on a real change.
